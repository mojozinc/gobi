3. Detailed Step-by-Step Flow

1
Mobile UI & State Management (Flutter)
User submits a question in HealthChatScreen. The screen appends the user message to ChatMessagesNotifier (Riverpod), displays a typing indicator, and collects the previous 6 message turns as conversation_history.
2
Self-Healing Network Request (ApiService)
ApiService resolves the dynamic LAN backend URL (via --dart-define=API_BASE_URL). If no token exists or if the server returns 401 Unauthorized (e.g. token expired), it automatically provisions a fresh guest token via loginAnonymously() and retries the request once.
3
Backend Routing & Authentication (FastAPI)
POST /api/v1/ai/chat receives the request. The get_current_user dependency validates the JWT Bearer token against PostgreSQL, identifying the authenticated user ID.
4
RAG Context Assembly (rag.py)
The backend builds a live snapshot from PostgreSQL containing:
  • Active Medications: Name, dosage, schedule times, inventory, intake notes.
  • Adherence Logs: Scheduled vs. actual taken times from the past 7 days.
  • Prescriptions: OCR extracts and doctor notes from uploaded documents.
5
Grounded LLM Generation (OpenRouter)
The health records are injected into the LLM system prompt. OpenRouter invokes meta-llama/llama-3.3-70b-instruct with temperature 0.3. If no API key is configured, a local fallback summary is returned.
6
Markdown Rendering & Tap-to-Retry UI
The response is returned to the phone and rendered using MarkdownBody. If a network drop or inference error occurs, a red error banner with an interactive "Tap to retry" button appears, and tapping the failed message allows editing.

4. The "Local SQLite vs. Cloud Postgres" Gap

Important Root Cause: Gobi is built as an offline-first mobile application. Medications added or seeded on the phone live in local SQLite (Drift). The AI backend RAG queries cloud PostgreSQL.

If you see medications in your mobile app UI, but the AI responds with "You currently don't have any active medications scheduled", here is why:

Local SQLite Storage
Drift Database (On Device)
Powers the Medications tab, Dose History charts, and offline tracking. Seeded test datasets live here.
Cloud PostgreSQL Storage
PostgreSQL (gobi-postgres)
Queried by the backend RAG builder when constructing the AI's prompt context.

When you create a medication in the app, MedicationsRepository writes to local SQLite immediately and fires an asynchronous background sync to PostgreSQL (_backgroundCloudCreate). If that sync failed or if sample data was only hydrated into local SQLite, PostgreSQL remains empty.

5. Why It Might Not Be Working As Intended

Observed Symptom Root Cause Expected Behavior & Fix
AI says "No active medications found" Medications exist only in local SQLite, not synced to backend PostgreSQL. Add medications while connected to the backend, or trigger cloud sync via MedicationsRepository.syncWithCloud().
AI doesn't add meds or check off doses Using /ai/chat (Q&A only) instead of /ai/parse-intent (Actions). The Chat screen is an informational assistant. To mutate data via voice/speech, use the Voice Assistant mic which triggers tool calling.
Chat gives a 401 Unauthorized error Stale token or app booted before backend was reachable. Our updated ApiService now auto-refreshes tokens and retries on 401 automatically.
Responses take 5 to 10 seconds 70B LLM inference latency over OpenRouter. Normal for high-parameter models (llama-3.3-70b-instruct). A typing indicator is displayed during generation.
Red error card: "Request failed" Network disconnection or OpenRouter API quota/key issue. Check backend container logs. Tap the red "Tap to retry" button once network is restored.

6. Debugging & Verification Checklist

Run these three commands from your terminal to verify every tier of the AI system:

1. Check Backend Debug Logs in Real-Time

docker compose -f backend-api/docker-compose.yml logs -f backend

Look for structured entries like --> POST /api/v1/ai/chat, query timings in [ms], and OpenRouter prompt dispatches.

2. Run the AI Chat Sanity Smoke Test

make smoke-chat

Tests backend health, guest authentication, and runs a live grounded query against the AI chat endpoint.

3. Run Automated Flutter & Backend Test Suites

# Mobile unit & smoke tests (24 tests)
cd gobi-mobile && flutter test

# Backend pytest suite (5 tests)
docker compose -f backend-api/docker-compose.yml exec backend pytest
